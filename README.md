## How I ship 3× faster without shipping worse

Spec-driven development with Claude Code, Cursor and Codex. The agent writes the code; I own the spec, the architecture, the review, and the consequences.

1. **Spec** — problem, constraints, acceptance criteria, data contract (human)
2. **Plan** — agent proposes a file-level plan; I approve or redirect
3. **Implement** — agent writes code + tests against the spec
4. **Review** — line-by-line human review, security & performance pass
5. **Ship** — CI, preview deploy, observability, rollback plan

Architecture decisions, data models and security boundaries stay human-owned. Always. Result: release cycles down ~40% with the same or lower defect rate.

## Principles

- **Numbers over adjectives.** If I can't say what moved, I haven't finished the job.
- **Structural wins before micro-optimisation.** Code splitting beat a hundred tiny tweaks. It usually does.
- **Boring in production.** Rollback plans, idempotent jobs, verified writes. Excitement belongs in the demo.
- **Leave it better.** Every codebase I've handed over came with CI, docs and a team that could run it without me.
